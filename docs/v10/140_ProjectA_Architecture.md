# 140. Project A Architecture

Project A is a preparation layer over existing contracts and orchestration:

```text
Healthy rollout supplied
  -> V7 dataset adapter and integrity validation
  -> V6/V8/V9 orchestration gates
  -> existing analysis, statistics, validation, and publication layers
  -> reviewed reports, figures, tables, and archive bundle
```

Project A adds specifications, templates, publication skeletons, and planning
tests. It does not add a manager, dashboard, kernel, runtime, plugin, scientific
algorithm, simulation, or new evidence.

The authoritative inputs are the V4 Healthy dataset schemas, the V5 campaign
matrix and campaign metadata, the existing Healthy configuration, and the
existing metric/assay modules. A missing dataset must remain
`WAITING_DATASET`.

## Protected boundaries

- No rollout is generated by the preparation package.
- No frozen evidence or manuscript is rewritten.
- No metric is upgraded into a biological endpoint.
- Real execution requires an approved dataset, provenance, integrity checks,
  and explicit authorization.
