# Preservation Checklist

This checklist records archival readiness. It does not claim that external
deposits already exist.

## GitHub Release

- [ ] Confirm Release `v1.0.0` points to the intended release commit.
- [ ] Confirm release notes use `docs/release/v1.0.0.md`.
- [ ] Confirm final report PDF, DOCX, and manifest are present.
- [ ] Confirm frozen evidence, figures, and tables are included.

## Zenodo

- [ ] Enable GitHub-Zenodo integration if desired by the project owner.
- [ ] Archive Release `v1.0.0`.
- [ ] Confirm metadata does not invent a journal publication or DOI.
- [ ] Add a DOI only after Zenodo mints one.

## Software Heritage

- [ ] Submit or verify archival of the GitHub repository.
- [ ] Record Software Heritage identifiers only after they exist.
- [ ] Preserve the source tree and release tag.

## OSF

- [ ] Create an OSF project only if needed for dissemination or journal policy.
- [ ] Upload the release snapshot or link to GitHub/Zenodo.
- [ ] Record OSF identifiers only after they exist.

## Figshare

- [ ] Create a Figshare deposit only if required by the selected venue.
- [ ] Include final report artifacts and curated evidence files.
- [ ] Record Figshare DOI or identifier only after it exists.

## Institutional Repositories

- [ ] Follow institutional repository metadata requirements.
- [ ] Preserve the computational scope and scientific boundary.
- [ ] Link back to the GitHub repository and Release `v1.0.0`.
